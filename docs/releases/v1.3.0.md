# HA Dashboard 1.3.0 Release Notes

Status: **Release candidate build 279 validated on 2026-10-08; tagging is
blocked by one open maintainer gate (see Acceptance checklist).**

Version 1.3.0 is a feature release built from `release/1.3.0`:

- The app is now translatable. Every piece of app text lives in `en.lproj`,
  with a contributor guide, a strict validation script, and a dedicated PR
  workflow.
- Entity states and attribute labels and values now use Home Assistant's own
  translated names, in the Home Assistant user's language. This fixes
  `not_home` appearing as raw text, reported by @psolyca in
  [issue #19](https://github.com/ha-dashboard/ios-app/issues/19).
- Lovelace cards the app cannot display now show a placeholder instead of
  silently disappearing, controlled by a new "Show Unsupported Cards" setting.
- Layout and stability fixes: light cards, the timer button row, `<ha-alert>`
  in markdown cards, a number-formatter thread-safety race, and crashes on
  malformed card configs.
- Developer tooling: the snapshot test runner works on Xcode 27 against
  pinned iOS 18 references.

1.3.0 ships in English only. No `fr.lproj` or other translation is included,
App Store metadata is not localised, and `CFBundleLocalizations` lists `en`
only in both `project.yml` and `HADashboard/Info.plist`. The language picker
in Settings therefore stays hidden in this release.

## App Store — What's New

New in 1.3.0

• Entity states now use Home Assistant's own wording in your Home Assistant
language. For example, a person who is away shows "Away" instead of
"not_home".
• Climate, humidifier and water heater modes, and what a thermostat is
currently doing, now match Home Assistant.
• Sensor text such as "Wi-Fi" is shown exactly as Home Assistant reports it.
• Cards HA Dash can't display yet now show a placeholder instead of
disappearing. Turn this off in Settings → Display → Show Unsupported Cards.
• Fixed overlapping text on light cards and a crowded timer button row.
• Fixed crashes caused by some unusual card configurations.

Thanks to @psolyca for reporting the untranslated states.

## App Review Notes

Version 1.3.0 adds no new permissions or data handling. It changes how entity
states are labelled: the app now requests Home Assistant's own translation
strings from the user's Home Assistant server over the existing authenticated
connection and caches them on the device, so states, modes and attribute
labels match the Home Assistant web interface. It also shows a placeholder for
dashboard cards the app cannot render, with a new on-by-default switch in
Settings → Display → Show Unsupported Cards. The app's own interface remains
English only in this version. Local Camera Stream and Home Assistant remote
controls are unchanged from 1.2.6; the 1.2.6 review notes for those features
still apply.

The app can be reviewed in Demo Mode without credentials. This version is
intentionally configured for manual release. Approval should leave it pending
developer release rather than publish it automatically.

## TestFlight — What to Test

1. **Translated states (#19):** with a person or device tracker that is away,
   confirm the card shows "Away", not "not_home". If your Home Assistant user's
   language is not English, confirm states and modes appear in that language,
   matching the Home Assistant web interface.
2. **Climate and similar devices:** check thermostat, humidifier and water
   heater cards. Mode buttons, the current action (heating, idle) and the
   detail screen's attribute names and values should match Home Assistant.
3. **Free-text sensors:** sensors with arbitrary text states (such as a Wi-Fi
   network name or an app name) must appear exactly as Home Assistant reports
   them, without added spaces or changed capitals.
4. **Offline start:** after one successful connection, turn off Wi-Fi and
   relaunch. States should still use the translated names.
5. **Unsupported cards:** on a dashboard with a custom card HA Dash does not
   support, confirm a placeholder names the card type. Turn off Settings →
   Display → Show Unsupported Cards and confirm the placeholder disappears
   without relaunching.
6. **Layout:** on a light card showing brightness and colour temperature,
   confirm the name, sliders and percentage don't overlap, and the timer
   card's buttons fit on one row at the same font size.

## Technical changelog

### App localisation (merged from `feature/i18n`)

- Added `HAStrings`, a localisation bundle resolver, and extracted all
  user-visible app strings across controllers, cells, views and the parser
  into `HADashboard/en.lproj/Localizable.strings` (315 keys at `4aebd92`).
- Added a Settings language picker built from the shipped `.lproj` folders.
  It persists an in-app language override and is hidden, header and content,
  while only `en.lproj` ships (cda01f5), so it appears automatically once a
  second language is merged.
- Added `scripts/check-translations.sh` (b1aae8d) with a `--strict` mode
  (3dad12d) that rejects partially translated languages, treats `%%` as a
  literal percent (82c1842), and runs `plutil -lint` over every `.strings` and
  `.stringsdict` file.
- Added the `Translations` workflow (`.github/workflows/translations.yml`,
  job `check-translations`) for pull requests touching `.lproj` content
  (66bd6b8). It needs no Xcode or secrets, so it is safe for fork PRs. CI also
  asserts that `en.lproj` is packaged in the app (df68eef).
- Added the contributor guide `docs/translations.md` (061bd33, e299570).
- Pinned `en_US_POSIX` for wire-format parsing so locale changes cannot break
  Home Assistant timestamp and number parsing (074c58e).

### Home Assistant translations for states and attributes (issue #19)

- Added `HAStateLocalizer` (1b406ea), which fetches Home Assistant's
  translation strings for the Home Assistant user's language over the
  WebSocket during the connect sequence (0d130f5).
- Routed every entity-state display through it (d500b72), including person
  and device tracker cards (c362ca8), climate and alarm mode buttons
  (864c9e7), the thermostat gauge's hvac mode label (837e708), and the media
  player source fallback label (c0fc999). Climate, humidifier and water heater
  modes and `hvac_action` use Home Assistant's names.
- Attribute names (b0854d3) and attribute values (8fb2b62) in the entity
  detail section now use Home Assistant's labels (51c32ae).
- `not_home` now renders as Home Assistant shows it: "Away" in English,
  "Absent" in French. A legacy fallback covers person and device tracker
  entities when no translations have loaded yet (d7b8d93, b40a994). States
  are capitalised the way Home Assistant displays them.
- Free-text states are never algorithmically reformatted (63a6814). Only
  domains with an enumerated state vocabulary are prettified when no
  translation exists, so a sensor state such as "YouTube" no longer becomes
  "You Tube".
- Translations are cached per language and reused on a cold or offline
  start. The resolved Home Assistant language is persisted so the right cache
  is selected before the first connection (64e1b90), and refreshes are
  debounced against the cache file's modification time (ab4e223).
- `HAEntityDisplayHelper` locks its shared `NSNumberFormatter` (00976d7).
- Added `HAStateLocalizerTests`, person/device tracker regression tests, and
  an end-to-end cold-start test with a French Home Assistant on an English
  device (9735084).

### Unsupported card placeholder (merged from `feature/unsupported-card-placeholder`)

- Cards the parser cannot map to any entity (unknown types, unmapped
  `custom:*` cards, and partially supported custom cards that yield no
  entities) now render as `HAUnsupportedCardCell`, which shows the raw card
  type and keeps the card's grid span and heading (bf51aa7). Known
  entity-optional built-ins and empty grid/stack containers are not
  placeholdered. Each distinct unsupported type is logged once per load.
- New "Show Unsupported Cards" toggle in Settings → Display, on by default.
  Changing it rebuilds the dashboard immediately from the cached Lovelace
  config (1e614a8). Its strings go through `HAStrings` (9638c5f).
- Conditional-card conditions are now applied once per item instead of twice.
  The duplicate was harmless (the conditions are ANDed) but redundant
  (1e614a8).
- Fixed crashes on malformed card configs: every `type` comparison in the
  parser now coerces non-string values, such as a numeric `type`, to nil
  instead of raising an unrecognised-selector exception (bf51aa7).
- Added `HAUnsupportedCardTests`, including five malformed-config shapes.

### Layout and stability fixes (merged from `fix/snapshot-test-runner`)

- Light cards report a content-aware preferred height, so the name,
  brightness and colour-temperature rows no longer overlap each other
  (12996e8).
- The timer button row uses equal-width buttons instead of overflowing fixed
  widths (7650674), with one shared font size across the row (cab879d).
- Markdown cards start `<ha-alert>` on its own line, like `<p>` and `<div>`
  (74cc91c).
- Stopped mutating a shared `NSNumberFormatter` from multiple threads
  (92b7f57).

### Developer tooling

None of these items change App Store or TestFlight behaviour.

- `scripts/test-snapshots.sh` works on macOS 27 / Xcode 27 (c6b4aae) and
  defaults to the pinned iOS 18.0 reference set (49955bd, 18acfb7, 0124c76).
  `testThermostatShowCurrentAsPrimary` now has a recorded reference
  (e2017b8), closing the 1.2.7 known boundary.
- `-only-testing` filters now narrow `test-snapshots.sh` runs instead of
  running, and in record mode re-recording, the whole target (a88d8f1).
- Test-harness fixes: snapshot cells are sized the way the app sizes them
  (1d5d806, 577411c); the markdown appearance test is hosted in a real window
  (3a25632); the cache-clear test waits for write completion (6bae65f); and
  the default tap-action tests match the current spec (9612b4e).
- `project.yml` excludes the `ReferenceImages/**` and `ReferenceImages_*/**`
  folders from the test target's sources.
- References re-recorded for the state-display changes (4aebd92).

## Known boundaries

- The App Store build still requires iOS 15. iOS 9–14 users must install the
  universal IPA from the GitHub release.
- 1.3.0 is English only. The language picker stays hidden until a second
  `.lproj` ships, and App Store metadata is not localised.
- The Settings UI (the toggle's placement in Display and the hidden language
  picker) and the timer button row were not driven on physical devices. They
  are covered by snapshot tests.
- Unknown `custom:*` cards that reference an entity are currently rendered by
  the generic entity fallback rather than the placeholder. This is the open
  gate below.
- Leaving "Show Unsupported Cards" off restores the previous behaviour of
  silently skipping those cards.
- Local Camera Stream boundaries are unchanged from 1.2.6.

### Deferred (not release-gating)

- iPad Mini 5: install only. The launch and visual check was deferred and is
  not claimed as passed. The iPhone 16 Pro Max on iOS 26 is the modern-device
  check for this release.
