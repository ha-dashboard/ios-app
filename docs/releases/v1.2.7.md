# HA Dashboard 1.2.7 Release Notes

Status: **Ready for release — release candidate build 195 validated on
2026-10-08.**

Version 1.2.7 is a bundled bug-fix release built from `release/1.2.7`:

- A crash when returning to a dashboard with a live (HLS) camera card
  ([issue #10](https://github.com/ha-dashboard/ios-app/issues/10)).
- The app now remembers the last-selected view for each dashboard across
  restarts ([issue #9](https://github.com/ha-dashboard/ios-app/issues/9)).
- A crash on tile cards whose `name` is an object, plus support for Home
  Assistant's entity-name config across cards and rows
  ([PR #17](https://github.com/ha-dashboard/ios-app/pull/17) by @metalix2,
  with follow-ups).
- Thermostat `show_current_as_primary` behaviour during +/− and drag
  ([PR #18](https://github.com/ha-dashboard/ios-app/pull/18) by @metalix2,
  with follow-ups).
- Developer tooling fixes (build-script signing, jailbroken-iPad deploy
  entitlements, Mini 4 launch arguments, screenshot trigger), release-pipeline
  changes, and README guidance for older devices.

The App Store/TestFlight packaging split (5bf14d2, 884af29) was already used by
the manual v1.2.6 replacement-build dispatch, but those commits postdate the
`v1.2.6` tag, so v1.2.7 is the first tag-triggered release to include them.

## App Store — What's New

New in 1.2.7

• Fixed a crash that could occur when returning to HA Dash, or opening it,
while a dashboard showed a live camera stream.
• HA Dash now reopens each dashboard on the view you last selected, instead of
always starting on the first view.
• Fixed a crash on tile cards that use an area or device as their name.
• Card and row names can now use Home Assistant's name options: area, device,
floor, entity, custom text, or a combination.
• Thermostats set to show the current temperature as the main number now keep
it there while you adjust the target, and the target updates live as you
drag.
• The target temperature no longer jumps back briefly when Home Assistant
sends an update just after you change it.

Thanks to @metalix2 for contributing the tile card name and thermostat fixes.

## App Review Notes

Version 1.2.7 is a bug-fix release with no new permissions or data handling. It
fixes a crash when HA Dash returns from the background to a dashboard
containing a live Home Assistant camera stream, remembers the last-selected
view for each dashboard, fixes a crash on tile cards
configured with an object `name`, adds support for Home Assistant's
entity-name configuration in card and row names, and improves the thermostat
card's current-temperature display. Local Camera Stream and Home Assistant
remote controls are unchanged from 1.2.6; the 1.2.6 review notes for those
features still apply.

The app can be reviewed in Demo Mode without credentials. Reproducing the fixed
camera crash requires a Home Assistant camera entity that supports streaming,
which Demo Mode does not provide. This version is intentionally configured for
manual release. Approval should leave it pending developer release rather than
publish it automatically.

## TestFlight — What to Test

1. **Live camera (#10):** add a camera card whose entity supports live
   streaming, with the card playing the live (HLS) stream. Press Home, wait,
   reopen HA Dash and repeat several times, then force-quit and relaunch.
   The app must not crash and the stream must resume once.
2. **Card names (PR #17):** set tile-card `name` to `{type: area}`,
   `{type: device}`, `{type: floor}`, `{type: text, text: ...}`, and an array
   such as `[{type: area}, {type: entity}]`. Confirm no crash and the expected
   text. Repeat for an entities-card row, a glance card, and a graph card.
   Confirm unknown types fall back to the entity name.
3. **Thermostat (PR #18):** on a thermostat card with
   `show_current_as_primary: true`, tap +/− and drag the arc. The large number
   must stay on the current room temperature while the target label updates
   live. After a tap, the target must not jump back before the change reaches
   Home Assistant.
4. **Remembered view (#9):** on a dashboard with several views, switch to a
   view other than the first, force-quit and relaunch. The app must reopen on
   that view. Switch dashboards and back and confirm each dashboard keeps its
   own view. Rename or remove the saved view in Home Assistant and confirm the
   app falls back to the first view.

## Technical changelog

### Remember last-selected view (issue #9)

- The last-selected Lovelace view is saved per dashboard (keyed by dashboard
  `url_path`) and restored on first load and when switching dashboards,
  instead of always resetting to view 0 (19d78f8). Restore matches the view's
  `path` first, then its index when the view has no path, and falls back to the
  first view when the saved view no longer exists. Views are saved from
  view-switcher taps and Home Assistant `navigate` commands. A WebSocket
  reconnect or refresh of the same dashboard keeps the current view. The
  `-HAViewIndex` launch argument still takes priority.
- Added `HAViewPersistenceTests` (5 tests).

### Live camera crash (issue #10)

- Fixed an `NSInternalInconsistencyException` crash on iOS 10 when returning
  from the background (or cold-launching onto the cached dashboard) with a live
  HLS camera card (58a3fea). The dashboard rebuilds twice on resume. The second
  rebuild stopped the camera cell and issued a second `camera/stream` request
  while the first was pending, so both responses started playback. The second
  replaced an `AVPlayerLayer` that was still key-value observed. `stopRefresh`
  now advances a request generation so stale responses are dropped, and
  `playHLSURL:` tears down any existing player and its observers before
  creating a new one. Live HLS playback is used only on iOS 10 and later;
  iOS 9 skips HLS, uses MJPEG, and is unaffected.
- Added `HACameraHLSTests` (3 tests).

### Entity-name config (PR #17 by @metalix2, plus follow-ups)

- Tile cards with an object `name` such as `{type: area}` or
  `{type: device}` crashed on load with an unrecognized selector, because the
  parser trimmed the dictionary as a string. They now resolve against the area
  and device registries (2622265, PR #17).
- Added `HAEntityNameResolver` as the single resolver for Home Assistant's
  entity-name config: a plain string, one `{type: ...}` object, or an array
  joined with a space. It supports `area`, `device`, `floor`, `text`, and
  `entity`. Inside an array, `entity` contributes the entity's registry name
  (else `original_name`) with any leading device-name prefix stripped. Unknown
  types such as `parent_device`, and malformed values, fall back to the entity
  display name (a365c9c, 4f8c84b, 69c3ddc, a733f9e).
- Routed every Lovelace `name` path through the resolver: tiles, standard
  single- and multi-entity cards, entities-card and badge rows, glance,
  mini-graph and history-graph per-entity configs, and mushroom chips
  (b083718).
- Device names now fall back to the registry `name` when `name_by_user` is
  JSON null (8ce76b5).
- Floor names now load reliably. The registries notification waits for the
  floor registry response, success or failure, and the floor-to-area mapping
  is built after all registries arrive (8bcd534).
- Known gap: Home Assistant's `next_name_part` registry flag is not available
  to the app, so device-prefix stripping is applied whenever a device name is
  known.
- Added `HAEntityNameResolverTests` (28), `HARegistryLoadingTests` (3), and
  new `HAClassicLayoutTests` cases.

### Thermostat show_current_as_primary (PR #18 by @metalix2, plus follow-ups)

- With `show_current_as_primary`, +/− nudges and arc drags no longer replace
  the large current-temperature label with the setpoint. The setpoint label
  updates instead (6f14c92, PR #18).
- While dragging the arc in that mode, the setpoint label now updates live
  (d10604f).
- An optimistic setpoint no longer snaps back when a Home Assistant state
  update arrives during the 5-second debounce. This applies to both single and
  dual (heat_cool) setpoints (d10604f).
- Consolidated the secondary-label construction into one helper.
- Added `HAThermostatPrimaryPolishTests` (7 tests, verified to fail before and
  pass after) and the snapshot test `testThermostatShowCurrentAsPrimary`,
  which has no recorded reference image yet.

### Developer tooling, build, release pipeline, and docs

None of the tooling items below change App Store or TestFlight behaviour.

- Deploy (ed5a9d1): the iPad 2/3 jailbreak SSH deploy re-signed on-device with
  `ldid` without an entitlements file, so the app had no
  application-identifier or team-identifier. Keychain writes then failed
  silently, and launch-argument credentials were lost on the next relaunch.
  The iPad 2/3 path now extracts and reapplies the signed entitlements, as the
  iPad 4 path already did. This affected only jailbroken developer deploys.
- Deploy (39fa555): `deploy.sh mini4` now passes launch arguments
  (`--dashboard`, `--kiosk`, `--server`), ending `idevicedebug` option parsing
  with `--`.
- Screenshot trigger (b9ee0c1, eebb69a): the developer screenshot trigger is
  checked by a 2-second repeating poll that runs only when the app is installed
  under `/Applications` (jailbroken SSH deploys) and stops after the first
  capture is scheduled. A one-off check also runs when the app becomes active
  and after a dashboard rebuild. The trigger directory now resolves through
  `NSTemporaryDirectory()` first, with the documented `/tmp` path as a
  fallback. Added `HAScreenshotTriggerTests` (5 tests).

- Build script (deed0bf): the universal device build re-signed with the first
  Apple Development identity in the keychain. With identities from more than
  one team, that certificate could be missing from the embedded provisioning
  profile, and stock iOS rejected the install with
  `ApplicationVerificationFailed` (0xe8008015). Jailbroken devices ignored the
  mismatch. It now re-signs with the certificate that signed the Xcode arm64
  template, falling back to the previous selection only when that certificate
  is not in the keychain. This is developer-facing; CI signing is unchanged.
- Release pipeline (5bf14d2): split packaging so App Store Connect receives a
  separately verified arm64/iOS 15 archive, while the universal armv7+arm64/iOS
  9 executable is used only for the GitHub, Ad Hoc, and direct-device IPA, and
  enforce a build-number floor above rejected build 162.
- CI (884af29): read the complete `xcodebuild -version` output when selecting
  Xcode 26/27.
- CI (9d37217): suppress signing-identity details in workflow logs and fail
  explicitly if certificate import, key access, or identity verification fails.
- README (8341ae4): explained that iOS 9–14 devices cannot receive new App Store
  updates and how to install the universal IPA by jailbreak or sideloading.

## Known boundaries

- The App Store build still requires iOS 15. iOS 9–14 users must install the
  universal IPA from the GitHub release to get these fixes.
- PR #18's +/− and drag behaviour is covered by unit tests. On a physical
  device, the thermostat card was checked for correct rendering on iPad 4 only;
  no physical tap or drag test was run.
- `testThermostatShowCurrentAsPrimary` fails until its reference image is
  recorded. Snapshot references are tied to an older simulator OS, and about
  445 snapshot tests already fail on the iOS 27 simulator. This predates this
  release; re-recording or OS-pinning the references is separate work.
- Entity-name config does not support `parent_device` and ignores
  `next_name_part`; both fall back as described above.
- Local Camera Stream boundaries are unchanged from 1.2.6.
