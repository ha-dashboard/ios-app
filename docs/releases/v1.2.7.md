# HA Dashboard 1.2.7 Release Notes

Status: **Draft — physical-device validation pending.**

Version 1.2.7 is a small bug-fix release. Its only application change fixes a
crash when returning to a dashboard that contains a live (HLS) camera card,
reported in [issue #10](https://github.com/ha-dashboard/ios-app/issues/10). The
remaining commits since the `v1.2.6` tag are release-pipeline and README
changes.

The App Store/TestFlight packaging split (5bf14d2, 884af29) was already used by
the manual v1.2.6 replacement-build dispatch, but those commits postdate the
`v1.2.6` tag, so v1.2.7 is the first tag-triggered release to include them.

## Distribution artifacts

- The App Store/TestFlight product is the separate pristine Xcode 26/27 archive:
  arm64 only, minimum iOS 15.0 in both its bundle and Mach-O load command.
- The universal armv7+arm64 IPA, with minimum iOS 9.0 in its bundle and both
  Mach-O slices, is attached to the GitHub release for iOS 9.3.3–14 devices
  (sideload or jailbreak) and direct-device installs. It is not the App Store
  binary.
- On iOS 9–14 the App Store only offers 1.2.5. Users on those versions,
  including the iOS 10 reporter of issue #10, receive this fix only through the
  universal GitHub IPA.
- The tag workflow derives the build number from the commit count, which must
  exceed the `APP_STORE_BUILD_NUMBER_FLOOR` of 162. Expected build: `<build>`.

## App Review Notes

Version 1.2.7 is a bug-fix release with no new features, permissions, or data
handling. It fixes a crash when HA Dash returns from the background to a
dashboard containing a live Home Assistant camera stream. Local Camera Stream
and Home Assistant remote controls are unchanged from 1.2.6; the 1.2.6 review
notes for those features still apply.

The app can be reviewed in Demo Mode without credentials. Reproducing the fixed
crash requires a Home Assistant camera entity that supports streaming, which
Demo Mode does not provide. This version is intentionally configured for manual
release. Approval should leave it pending developer release rather than
publish it automatically.

## TestFlight — What to Test

1. Add a Home Assistant camera card whose entity supports live streaming, and
   set the camera stream mode so the card plays the live (HLS) stream.
2. With the dashboard open and the stream playing, press Home, wait a few
   seconds, and reopen HA Dash. Repeat several times. The app must not crash
   and the stream must resume.
3. Force-quit and relaunch so the cached dashboard is shown first, then
   confirm the live stream starts once and the app stays open.
4. Switch views or dashboards while the stream is loading and confirm no crash
   or duplicate playback.

## Technical changelog

- Fixed an `NSInternalInconsistencyException` crash on iOS 10 when returning
  from the background (or cold-launching onto the cached dashboard) with a live
  HLS camera card (58a3fea, issue #10). The dashboard rebuilds twice on resume;
  the second rebuild stopped the camera cell and issued a second
  `camera/stream` request while the first was pending, so both responses
  started playback. The second replaced an `AVPlayerLayer` that was still
  key-value observed. `stopRefresh` now advances a request generation so stale
  responses are dropped, and `playHLSURL:` tears down any existing player and
  its observers before creating a new one. Live HLS playback is used only on
  iOS 10 and later; iOS 9 skips HLS, uses MJPEG, and is unaffected.
- Added `HADashboardTests/HACameraHLSTests.m` regression tests: replaying
  releases the previous player's observers, and a stale or post-stop
  `camera/stream` response does not start playback.
- Release pipeline (5bf14d2): split packaging so App Store Connect receives a
  separately verified arm64/iOS 15 archive, while the universal armv7+arm64/iOS
  9 executable is used only for the GitHub, Ad Hoc, and direct-device IPA, and
  enforce a build-number floor above rejected build 162.
- CI (884af29): read the complete `xcodebuild -version` output when selecting
  Xcode 26/27.
- CI (9d37217): suppress signing-identity details in workflow logs and fail
  explicitly if certificate import, key access, or identity verification fails.
- README (8341ae4): explained that iOS 9–14 devices cannot receive new App Store
  updates and how to install the universal IPA by jailbreak or sideloading.

## Known boundaries

- The App Store build still requires iOS 15. iOS 9–14 users must install the
  universal IPA from the GitHub release to get this fix.
- `HADashboardTests` on the iOS 27 simulator has 445 pre-existing failures,
  mostly snapshot reference mismatches on that simulator OS. They predate this
  release and are not caused by it; re-recording or OS-pinning snapshot
  references is separate work.
- Local Camera Stream boundaries are unchanged from 1.2.6.
