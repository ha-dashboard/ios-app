# HA Dashboard 1.2.7

These are the public notes for the v1.2.7 tag workflow.

## Fixes

- The app now remembers the last-selected view for each dashboard across
  restarts, instead of always opening on the first view. It restores by view
  path, then by position, and falls back to the first view if the saved one no
  longer exists. The `-HAViewIndex` launch argument still overrides it.
  Resolves [#9](https://github.com/ha-dashboard/ios-app/issues/9).
- Fixed a crash when returning to HA Dashboard from the background, or
  launching it onto the cached dashboard, while a dashboard showed a live (HLS)
  camera card. Two overlapping camera stream responses could both start
  playback, and the second replaced a video layer that was still being
  observed. Stale responses are now ignored and the old player is released
  before a new one starts. Reported on iOS 10 in
  [#10](https://github.com/ha-dashboard/ios-app/issues/10) and verified on a
  real iOS 10.3.3 iPad 4.
- Fixed a crash when loading a tile card whose `name` is an object, such as
  `{type: area}`. Thanks to @metalix2 for
  [#17](https://github.com/ha-dashboard/ios-app/pull/17).
- With `show_current_as_primary`, the thermostat card now keeps the current
  temperature as the large number during +/− and drag, and the setpoint label
  updates live, including mid-drag. An optimistic setpoint also no longer snaps
  back when a Home Assistant update arrives during the 5-second debounce.
  Thanks to @metalix2 for
  [#18](https://github.com/ha-dashboard/ios-app/pull/18).

## Entity name options

Card and row names now support Home Assistant's entity-name config in tiles,
entities-card rows, glance and graph cards, and chips:

- `area`, `device`, `floor`, `entity`, and `text` items.
- An array of items joined by a space. The `entity` part drops a leading
  device-name prefix, so `[{type: device}, {type: entity}]` does not repeat
  the device name.
- Device names fall back to the device's own name when no custom name is set,
  and floor names now load reliably.

Unsupported types such as `parent_device` fall back to the entity's normal
name.

## Other changes

- The README now explains how iOS 9–14 devices can get updates.
- The build script now re-signs the universal app with the certificate that
  signed its provisioning template. Previously it could pick another team's
  certificate when several were installed, and stock iOS refused the install.
- Developer deploy fixes: jailbroken iPad 2/3 installs keep their signing
  entitlements, so saved credentials survive a relaunch; `deploy.sh mini4`
  passes launch arguments; and the developer screenshot trigger is polled only
  on `/Applications` installs and stops after the first capture. These do not
  change App Store, TestFlight, or sideloaded IPA installs.
- The release workflow now builds the App Store archive (arm64, iOS 15+)
  separately from the universal armv7+arm64 IPA, reads the complete Xcode
  version output, and keeps signing-identity details out of CI logs.

## Which build to install

- **iOS 15 and later:** update from the
  [App Store](https://apps.apple.com/gb/app/ha-dash/id6759347912).
- **iOS 9.3.3 – 14.x:** the App Store only offers 1.2.5 on these versions, so
  **these fixes, including the iOS 10 crash fix for #10, are only available
  from the universal IPA attached to this release.** Install it on a
  jailbroken device with AppSync Unified or a similar tool, or sideload it with
  a tool such as Sideloadly. With a free Apple ID, sideloaded apps must be
  re-signed every 7 days.

The universal IPA supports armv7 and arm64, with a minimum of iOS 9.0 in both
slices. Local Camera Stream still requires iOS 10.3.3 or later; Local Camera
Stream and remote-control behavior are unchanged from 1.2.6.

When reporting a bug, include your device, iOS version, and app version
(Settings → version).
